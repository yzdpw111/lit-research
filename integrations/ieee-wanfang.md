# 接法示例：ieee-research / wanfang-research

> ⚠️ **这是"接法示例"，不是依赖。**
> `lit-research` 的规范（`standards/`）**不绑定任何具体来源**；本文只是把两个常见来源**怎么接**写下来，
> 顺便记录**它们特有的**已知限制。换用别的来源（CNKI / arXiv / Google Scholar / Zotero…）时，
> 照 `S-07 §7` 的通用条款自己接即可，**不必读本文**。

---

## 1. 怎么接（两行环境变量）

```powershell
# 把日志/落盘结果指到"来源目录"（而不是都塞进一个 logs/）
$env:IE_LOGS_DIR = "<课题目录>\01_检索\ieee\raw"
$env:WF_LOGS_DIR = "<课题目录>\01_检索\wanfang\raw"
```

对应 `lit.config.json`：

```json
{ "sources": ["ieee", "wanfang"] }
```

然后 `01_检索/<来源>/检索式.md` 留档（关键词组 + 命中数 + 日期），原始 JSON 落在 `raw/`（只读）。

**约束**：两个工具的抓取脚本都要求**在各自仓库根目录**执行（`python scripts/xxx.py`），
且**启动 Chrome 需要放行沙箱**（受限沙箱下 Chrome 会启动即自杀）——这是它们的运行前提，与本规范无关。

---

## 2. 这两个来源**特有**的已知限制（通用规范不覆盖这些）

> 这些是**特定数据源**的行为，不是 `lit-research` 的规定。
> 换来源时**请自己核对**有没有同类问题。

| 限制 | 影响 | 对策 |
|---|---|---|
| **万方不返回刊名** | GB/T 7714 的 `[J]` 缺必备字段 | 去另一来源找同篇；或从 PDF 取刊名；**取不到就别用**（宁缺勿造） |
| **万方部分期刊不提供参考文献区块** | `references` 字段直接不出现 | 该文献的参考文献**下沉到 PDF 全文里找**；别据此改抓取逻辑 |
| **IEEE 页面不返回 `citedBy`** | **无法按被引数筛"经典文献"** | 容量规划里**强制留一类"经典/奠基"配额**，别只按相关度排序 |
| 详情/下载需**机构访问**；`hasInstitutionalAccess` 是**页面级**检测 | 与 PDF 接口级权限**可能不一致** | 只认"**下到了真 PDF**"（`%PDF-` 开头且非 HTML）才算拿到 |
| **万方静默限流**（页面正常但 0 条） | 会被误当成"没有结果" | 冷却几分钟重试；把它归入失败分类的**"限流"**类 |
| 万方**人机验证滑条**会被报成"页面加载超时" | 误诊 | 人工拖一次滑条再重跑，**别连续重试** |
| 下载**顺序执行、间隔 8–18s** | 几百条要跑数小时 | 分批 + 进度文件（规范 §5 的失败清单正好承接） |

---

## 3. 它们**不是**特有、属于**通用**的问题（已进规范，本文不重复）

这几条看起来像"工具的缺陷"，其实是**任何检索来源 + 任何 agent 调研流程都会有的**，
所以已经写进 `standards/`，**不在这里**：

| 通用问题 | 在哪 |
|---|---|
| 拿摘要/snippet 当全文 | `S-01 证据与档位` |
| 没有容量定标 | `S-02 容量与比例` |
| 跨数据集并排比大小 | `S-03 可比性` |
| 原文矛盾 / 读不出 / 失败无分类 | `S-04 诚实与不确定性` |
| 题录字段缺失 | `S-05 著录` |
| 目录乱套 | `S-07 目录与产物` |
