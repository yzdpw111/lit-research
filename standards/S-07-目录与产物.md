# S-07 · 目录与产物

> **条款编号可被引用**：如 `见 S-07 §4.2`。
> 每条给 **规定 → 依据 → 违反后果 → 检查方式**（`lit layout` 的 code）。
> **依据档位**：`full_text`＝实测踩过；`abstract_only`＝只从上游文档读出；`inference`＝推断，未验证。

---

## §1 总则

**§1.1** 一次调研 = **一个课题目录**，目录名即课题名。
> 依据：`full_text`（实战中一个课题一个目录，跨课题混放会毁掉引用关系）

**§1.2** 目录内分**阶段编号**（`00_`～`07_`），**阶段内按来源再分**（`ieee/`、`wanfang/`）。
> 依据：`source_conflict` —— 上游两个 skill 的文档给的是**按产物类型**分（`01_摘要库/02_精读论文/…`），
> 而实测更该**按来源+阶段**分（否则两个来源的原始件与日志混在一起，去重与 `logPath` 定位都难）。
> **两套并存就是乱套的源头，故本规范唯一裁定"阶段 → 来源"两层。**

**§1.3** 目录结构如下（**唯一合法形态**）：

```
<课题目录>/
├── README.md                        目标 / 范围 / 容量目标 / 进度
├── lit.config.json                  ★ 容量与档位定义（所有规范数值的唯一出处）
├── 00_方向地图/
│   ├── 方向地图.md
│   ├── 线-NN_<线名>.md
│   └── 收敛决定.md
├── 01_检索/
│   ├── ieee/
│   │   ├── raw/                     ★ 只读证据区
│   │   └── 检索式.md
│   ├── wanfang/
│   │   ├── raw/                     ★ 只读证据区
│   │   └── 检索式.md
│   └── 去重报告.md
├── 02_候选库/
│   ├── refs.json                    ★ 唯一权威题录库
│   ├── 档位表.md
│   └── 排除清单.md
├── 03_全文/
│   ├── pdf/<ID>.pdf
│   ├── text/<ID>.txt
│   └── 获取失败.md
├── 04_精读/
│   ├── <ID>.md
│   └── 精读汇总.md
├── 05_聚合/
│   ├── 数据集对比表.md
│   ├── 指标对比表.md
│   └── 章节结构统计.md               （学位论文调研特有）
├── 06_综述/
│   ├── 综述提纲.md
│   ├── 综述.md
│   └── 参考文献.md
└── 07_核验/
    ├── lit-audit.json
    └── 交付核查.md
```

**§1.4** 顶层**只允许**上述条目。放别的东西（草稿、临时件、参考资料）请另建目录，**不要塞进课题目录**。
> 检查：`LAYOUT_UNKNOWN_TOP`

## §2 ID：唯一引用键

**§2.1** 每篇文献有**唯一 ID**，形如 `IEEE:<arnumber>` 或 `WF:<文档ID>`。
**任何地方引用文献都用 ID，不用标题。**

> 依据：`full_text` —— 实战中遇到**两篇题名几乎相同的学位论文**（同一研究方向、同一导师组），
> 按题名反推编号时**把两条并成了一条**；后来改成显式 ID 映射才修好。

**§2.2** ID 在 `02_候选库/refs.json` 里**必须唯一**，且**每篇必须有 `tier` 字段**（见 S-01）。
> 检查：`LAYOUT_DUP_ID` / `LAYOUT_MISSING_TIER` / `LAYOUT_BAD_TIER`

**§2.3** 产物 Markdown 里出现 `[IEEE:x]` / `[WF:y]` 形式的引用，**必须能在 `refs.json` 里找到**。
> 检查：`LAYOUT_DANGLING_CITE`

## §3 只读证据区

**§3.1** 以下目录是**只读证据区**，进去的文件**一个字不许改、不许改名、不许删**：
- `01_检索/*/raw/`（上游抓取工具落盘的原始产物）
- `03_全文/pdf/`、`03_全文/text/`

> 依据：`full_text` —— 全链路要可回溯；**改写证据 = 毁证**。
> 检查：`LAYOUT_RAW_NON_JSON`（`raw/` 里只许 `.json` 与 `.log`）/ `LAYOUT_ID_FILENAME`（`pdf|text` 下文件名必须是 `<ID>`）

**§3.1.1** ★ `raw/` 里**允许 `.log`**——抓取工具会把**自己的启动日志**（典型是 `chrome-launch.log`）
写进 `§7.3` 要求的那个目录，**冲突在规范这一侧**：是规范要求把日志变量指到 `raw/`，
而工具顺带也写自己的启动日志。**实测被它挡住两次**（清掉之后跑一次抓取又出现）。
这些日志同属"原始落盘"，**不报错**；只报既非 `.json` 也非 `.log` 的文件。

**§3.2** `03_全文/pdf|text/` 的文件名**就是 ID**（`IEEE_11181461.pdf`），**不许用论文标题**。
> 依据：`full_text` —— 标题会重名、会随改版变动、含非法字符；用 ID 才与 `refs.json` 一一对应。
> 检查：`LAYOUT_ID_FILENAME`

**§3.2.1** ★ **改名必须自动化，不许手改**：用 `lit link` —— 它读**下载日志里的权威映射**
（`<来源>_paper_download-*.json` 记录了 `arnumber`/`url` ↔ 落盘路径），把题名命名的文件入库成 `<ID>.pdf`。
**硬约束：只用权威映射，绝不按题名匹配**——映射不上就报错。
> 依据：`full_text` —— **实测踩过**：手工用题名模糊匹配改名，**配错了一篇**，
> 并在修补时**把那篇 PDF 删掉了**。根因不是粗心，是**规范当时没给自动化手段，逼人做最容易错的一步**。
> 源文件**已在课题目录内** → `link` 用**改名**（move，不留题名残件）；在目录**外** → **复制**（保留用户原文件）。
> 检查：`LAYOUT_ID_FILENAME`（残留题名文件会被报出来）

**§3.3** 只读区的完整性用**封存清单**保证：`lit layout --seal` 生成哈希清单，之后 `lit layout` 校验。
> 检查：`LAYOUT_SEAL_CHANGED` / `LAYOUT_SEAL_MISSING`

## §4 数值与档位：**只在一处**

**§4.1** **所有规范数值**（容量、比例、阈值、档位白名单）**只在 `lit.config.json`**。
Markdown 里**引用**它们，**不许重写**。
> 依据：`full_text` —— 同一数值两处必然漂移；实战中"参考文献 ≥80（博士）/ ≥40（硕士）"**被 Lead 搞错过一次**，
> 导致给下级的指标翻倍。**检查：** `LAYOUT_HARD_NUMBER_IN_PROSE`

**§4.2** 每篇文献的证据档位**只写在 `02_候选库/refs.json`**；
笔记、综述、对比表**引用档位，不重新声明**。
> 依据：`inference`（未直接踩坑，但与 §4.1 同理：档位散落会出现"同一来源两种说法"）

## §5 失败与排除必须有清单

**§5.1** 凡发生下载动作，**必须**产出 `03_全文/获取失败.md`（**分五类**：未订阅 / 书·标准 / 非 PDF 权限页 / 站点改版 / 限流）。
**§5.2** 凡发生筛选动作，**必须**产出 `02_候选库/排除清单.md`（条 + 原因）。
> 依据：`full_text` —— 实战中"**下不到的清单比下到几篇更有价值**"，但它当时只是报告里的一句话，
> 没有变成产物，复盘时无法定位"到底哪些没拿到、为什么"。
> 检查：`LAYOUT_MISSING_FAILURE_LIST`

---

## §6 目录只增不改名

**§6.1** **不许重命名既有目录**（阶段目录、来源目录、只读区都不许）。
新需求 → **加新阶段编号**。
> 依据：`full_text` —— 实战中改名会让所有**路径式引用**（`references/xxx.md`、笔记里的 PDF 路径）**全断**。
> 检查：`LAYOUT_DUP_STAGE`（同一阶段编号出现多个目录，通常是改名留下的残骸）

## §7 来源接入（**不绑定任何具体来源**）

**§7.1** 一个课题目录可以有**任意多个来源**，来源名单**写在 `lit.config.json` 的 `sources`**：
```json
{ "sources": ["ieee", "wanfang"] }
```
> **本规范不绑定任何具体检索工具**：换成 `["arxiv","cnki","scholar"]` 或加 Zotero 导出的来源，同样合规。
> 规范只管"**来源要分开、原始件只读、检索式留档**"，不管来源是什么。
> 依据：`inference` —— 绑定具体工具会让规范随工具失效。**检查：** `sources` 里的每个名字都应在 `01_检索/<来源>/` 下有对应目录。

**§7.2** **检索式必须留档**（`01_检索/<来源>/检索式.md`：关键词组 + 命中数 + 日期），否则调研**不可复现**。
> 检查：`LAYOUT_MISSING_QUERY_LOG`

**§7.3** 若某个来源的抓取工具支持"把日志/结果落盘到指定目录"，**应当指到 `01_检索/<来源>/raw/`**
——这样**来源天然分离**，且落在只读证据区（§3.1）。
> 依据：`abstract_only` —— 上游工具的文档只提醒"把日志指到某个 `logs/`，避免散落在各处"，
> 但**没解决"多个来源混在一起"**；本规范进一步固定到**来源目录**。
> ⚠️ **具体某个来源怎么配，见 `integrations/` 下的对应文档——那是"接法示例"，不是依赖。**

## §8 检查器

| code | 含义 |
|---|---|
| `LAYOUT_UNKNOWN_TOP` | 顶层出现白名单外的条目 |
| `LAYOUT_DUP_STAGE` | 同一阶段编号有多个目录（改名残骸） |
| `LAYOUT_DUP_ID` | `refs.json` 里 ID 重复 |
| `LAYOUT_MISSING_TIER` | 某篇缺 `tier` |
| `LAYOUT_BAD_TIER` | `tier` 不在白名单（见 S-01） |
| `LAYOUT_DANGLING_CITE` | 引用了 `refs.json` 里没有的 ID |
| `LAYOUT_RAW_NON_JSON` | `raw/` 里有非 `.json` |
| `LAYOUT_ID_FILENAME` | `pdf|text` 下文件名不是 ID |
| `LAYOUT_HARD_NUMBER_IN_PROSE` | Markdown 里写死了规范数值 |
| `LAYOUT_MISSING_FAILURE_LIST` | 有获取/筛选动作却没有失败清单 |
| `LAYOUT_MISSING_QUERY_LOG` | 缺检索式留档 |
| `LAYOUT_SEAL_CHANGED` / `LAYOUT_SEAL_MISSING` | 只读区被封存后又被改动 / 缺封存清单 |
