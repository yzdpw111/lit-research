# lit-research · 学术调研的通用规范参考

> **配套 skill**：[`ieee-research`](https://github.com/yzdpw111/ieee-research) · [`wanfang-research`](https://github.com/yzdpw111/wanfang-research)
> （但**不绑定它们**：来源名单写在课题的 `lit.config.json` 里，换 CNKI / arXiv / Google Scholar / Zotero 同样合规）

`lit-research` 是**检索之后的「规范层」**。它**不替你检索**、**也不替你写作**，只规定四件事：

| 它规定什么 | |
|---|---|
| **什么算合格** | 六档证据、容量（承诺 vs 兑现）、可比性红线 |
| **什么不许做** | 不许拿摘要当全文、不许编造、不许把不可比的东西并排 |
| **产物该放哪** | 目录树 + 六条防乱套硬规矩 |
| **怎么自检** | 八个子命令，规范可被机器验证 |

**适用任何文献调研**：预研摸底 · 技术选型 · 学位论文 · 期刊投稿 · 基金申请。

> ⚠️ **它不假定你有外部规定。** 容量条数、著录风格、来源名单**都由你给**：
> 有外部规范（学位规范 / 期刊指南 / 基金要求）就按它并**记下出处**；
> **没有就自己承诺一个数，写进 `capacity.source`**。
> 检查的是「**承诺 vs 兑现**」——**不是"你违抗了谁的规定"**。前者可讨论，后者只能服从。

**流程可以各人各样，规范必须唯一** —— 所以它的组织形态是
`standards/`（条款，可逐条引用）+ `assets/`（模板）+ `integrations/`（接法示例）
+ `scripts/lit_cli.py`（唯一可执行的部分）。

> 规范如果不能被验证，就只是口号。这是本 skill 只有一个脚本、却有 7 份条款的原因。

---

## 为什么需要它

一次真实的调研里，最容易出的不是"搜不到"，而是**搜到了却用错**：

| 症状 | 后果 |
|---|---|
| 拿摘要当全文 | 数值来自摘要，但论文正文根本不支持 → **编造** |
| 同一个数据集的不同子集并排比大小 | 结论不成立，但没人发现 |
| 原文自身前后矛盾，自己挑一个写 | **替原文圆场＝伪造** |
| 扫件抽不出文字，当读过了 | 引用一篇根本没读的文献 |
| 下不到的文献只在报告里提一句 | 复盘时查不出"到底哪些没拿到、为什么" |
| 文献文件按题名命名 | 两篇题名相似就配错，**而且配错后很难发现** |

这些都不是"检索能力"能解决的，是**纪律**问题。

## 七份条款

| 条款 | 管什么 |
|---|---|
| **S-01 证据与档位** | 六档：`full_text` / `abstract_only` / `unreadable` / `source_conflict` / `insufficient_evidence` / `bad_source`，以及**每档允许做什么、不许做什么** |
| **S-02 容量与比例** | 数值只放配置；**硬线必须显式给出**（不替你猜）；缺 config/refs 时报错而**不是放过** |
| **S-03 可比性** | 三条红线：同一数据集不同子集 / 不同数据集 / 跨任务 —— **一律不许直接横比** |
| **S-04 诚实与不确定性** | 禁编造 · 原文矛盾**并列不取舍** · 读不出如实标 · 证据不足就停 · 失败分五类 |
| **S-05 著录** | 只输出真实字段；区分「缺字段」「**字段不可靠**」「流程中态」三种情形 |
| **S-06 方向选择** | 方向地图的固定列 · 并行探索的同构要求 · **停止与收敛判据** |
| **S-07 目录与产物** | 目录树 · 六条防乱套硬规矩 · 只读证据区 |

每一条都带 **依据档位**：`full_text`（实测踩过）/ `abstract_only`（只从文档读出）/ `inference`（推断未验证）。
**不确定的就标不确定，不许把推断写成实测。**

## 八个子命令

```powershell
lit plan       "<课题>" --refs-min 40 --now-year 2026     # 定容量：硬线必须显式给
lit ingest     "<课题>"                                    # 落盘 JSON → refs.json（带档位）
lit link       "<课题>"                                    # PDF 按权威映射入库成 <ID>.pdf
lit note       "<课题>" --id IEEE:11181461                 # PDF → 带页码全文
lit refs       "<课题>" --write                            # GB/T 7714 著录 + 硬指标核查
lit layout     "<课题>"                                    # 目录结构合规
lit audit      "<课题>"                                    # 档位 / 容量 / 数字出处 / 可比性 / 著录
lit selfcheck                                              # 检查本 skill 自己的文档
```

几条**刻意设计**的取舍：

| 命令 | 设计 | 为什么 |
|---|---|---|
| `plan` | **不内置任何硬线**，不给就报错；`--source` 记下出处 | **每个产出的约定来源各不相同**（外部规范 / 期刊指南 / 基金要求 / **或你自己承诺**）；**猜一个数比报错更坏** |
| `lit refs` | `refs_style` 可配（默认 `gb7714`）；选了别的会**明确说"我没做"** | 绝不假装支持另一种著录风格 |
| `ingest` / `note` | 档位**只往下判，不往上判** | 有全文才 `full_text`；**不会因为"看起来重要"就升档** |
| `ingest` / `note` | **人工档位优先**（`tier_source: "manual"`） | 重跑不许覆盖人的判断 |
| `link` | 只用**下载日志的权威映射**，匹配不上就报错 | 曾用题名模糊匹配 → **配错一篇，并在修补时删掉了它** |
| `note` | 抽不出文字给 `unreadable`，且**不写空文件** | 空 `.txt` 会让下游以为"读过全文了" |
| `refs` | **按正文引用顺序**编号；不编卷(期):页码 | GB/T 7714 要求引用序；缺的字段**留空并登记** |
| `layout` / `audit` | 缺前置时报错，**不报"通过"** | 曾经是"恒真检查器"：什么都没查却报合规 |
| `selfcheck` | 检查 skill **自己**的文档 | `layout` 只看课题目录，看不到 skill 自身的悬空引用 |

## 安装

把本仓库放到 `~/.dsh/skills/`（或 `~/.claude/skills/`）即可。无第三方依赖
（只有 `note` 用到 PyMuPDF，`pip install PyMuPDF`）。

**它不是执行器**：agent 用它**查条款**、**跑检查**，而不是被流程推着走。

## 一次真实小课题实战：11 个缺陷，全部只在真跑时暴露

课题「**基于深度学习的锂离子电池健康状态（SOH）估计**」，完整走了一遍：

```
检索 983 条 → 详情 20/20 → 下载 4/4 → 全文 4 篇 → 精读 4 份
→ 聚合（数据集/指标/章节结构）→ 综述 → 44 条 GB/T 7714 著录
```

**合成的 3 条 fixture 全绿时测不到的缺陷，被真实数据炸出来 11 个**，其中 6 个是规范/检查器自身的：

| # | 缺陷 | 修法 |
|---|---|---|
| 1 | **`audit` 是恒真检查器** —— 缺 config/refs 时什么都没查，却报「合规通过」 | 报错，**宁可报"查不了"** |
| 2 | `needs_detail` 标记清不掉 → 警告永不消失 | 抓到详情时清掉 |
| 3 | **没有「排除」机制** → `ingest` 每次把坏记录加回来 | 补 `excluded` + S-05 §1.6 |
| 4 | `近 N 年`、`41 / 1`、引用块复述 → **三处正则假阳性** | 收紧；引用块算论述不算断言 |
| 5 | 抓取工具把**自己的启动日志写进只读区** | **规范让步**：`raw/` 允许 `.log` |
| 6 | 检索记录缺 `lang` → 外文比例被算成 27%（真实 67%） | 由来源即可确定，全部补上 |

还有**我自己犯的错**：曾用**题名模糊匹配**给 PDF 改名，**配错一篇、并在修补时删掉了它**。
这就是 `link` 只认**权威映射**、**绝不猜**的由来。

### 规范在真实数据上真的挡住了我

拿到 4 篇全文的数值后，我本来要拼一张对比表：

| 论文 | 指标 | 值 | 数据集 |
|---|---|---|---|
| A | **MAE** | 0.00556 | 5 电池退化集 |
| B | **RMSE** | 0.0112 | NASA PCoE |
| C | **RMSE** | 1.60% | Oxford |

**并排比会得出「A 最好」——全错**：MAE ≠ RMSE（量纲错误）、数据集不同、
`0.0112` 是小数而 `1.60%` 是百分数。按 **S-03** 拆成四组、不做跨组排序，
并专门写了一节「**一个真实的陷阱**」。

> **规范不是给人加负担的，它是唯一挡住"写一个看起来漂亮但错的表"的东西。**

## 已知边界（如实）

- **它不能判断"方向对不对"** —— 方向地图的列被固定了，但**空位判断是否成立**只能靠人
- **它不能判断"文献选得对不"** —— 需要语义判断，检查器做不到（各条款里都写明了"本条款没有自动检查的部分"）
- **`AUDIT_NUMBER_WITHOUT_SOURCE` 精确率不够** —— 会有低价值警告，实际使用时有"狼来了"风险
- **只在一个 45 条的小课题上压过测**，且其中 40 条是 `abstract_only`
  → **"有 20 篇全文时规范还挡不挡得住"，尚未验证**
